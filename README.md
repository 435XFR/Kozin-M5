# Practical_04_MavlinkGroundStation

Учебная наземная станция управления (НСУ) на **Qt Widgets** с UDP-каналом связи и протоколом **MAVLink**, а также эмулятор БПЛА.

Практическое занятие №4: «Сетевая связь НСУ и БПЛА: QUdpSocket, MAVLink, телеметрия и команды».

## Возможности

- Приём UDP-датаграмм через `QUdpSocket` (порт по умолчанию `14540`).
- Разбор MAVLink-телеметрии (`HEARTBEAT`, `GLOBAL_POSITION_INT`) и отображение широты, долготы, высоты и режима полёта.
- Подсчёт принятых и потерянных пакетов по полю `seq`.
- Отправка команды взлёта `MAV_CMD_NAV_TAKEOFF` (`COMMAND_LONG`) и обработка `COMMAND_ACK`.
- Обнаружение потери связи (нет пакетов более 3 секунд), повреждённых пакетов и отсутствия подтверждения команды.
- **Безопасный режим НСУ** (задание 4, вариант 3): при потере связи блокируются кнопки «Взлёт», «Посадка», «Стоп».
- Журнал событий с временем, типом и причиной.
- Эмулятор БПЛА с имитацией потери связи и повреждения пакетов.

## Безопасный режим

| Событие | Реакция НСУ |
|---|---|
| Потеря связи (> 3 с без пакетов) | красный статус «Связь потеряна», кнопки «Взлёт», «Посадка», «Стоп» заблокированы, запись в журнале |
| Восстановление связи | зелёный статус, кнопки разблокированы, уведомление «Связь восстановлена», запись в журнале |
| Нажатие команды без связи | команда не отправляется, выводится предупреждение |

## Архитектура

```
Practical_04_MavlinkGroundStation/
├── CMakeLists.txt
├── main.cpp
├── mainwindow.h / .cpp / .ui     # представление (GUI)
├── mavlinkmanager.h / .cpp       # сетевой слой: QUdpSocket, MAVLink
├── mavlinkmessageparser.h / .cpp # проверка и разбор пакетов
├── telemetrymodel.h / .cpp       # модель: последнее состояние БПЛА
└── uavsimulator.h / .cpp         # эмулятор БПЛА
```

Принципы:

- В `MavlinkManager`, `TelemetryModel`, `UavSimulator`, `MavlinkMessageParser` нет обращений к `ui->`.
- В `MainWindow` нет разбора MAVLink, расчёта CRC и формирования датаграмм.
- События передаются в GUI только через сигналы и слоты (указательный синтаксис `connect`).
- Входящие датаграммы читаются в цикле `while (hasPendingDatagrams())`.
- Адрес и порт отправителя берутся из `QNetworkDatagram`.
- Команда считается выполненной только после `COMMAND_ACK`.

## Требования

- Qt 6 (Widgets, Network, Charts) или Qt 5.15
- CMake 3.16+ (или qmake)
- Компилятор с поддержкой C++17
- Сгенерированная библиотека MAVLink для C++ (рекомендуется) или упрощённый учебный парсер

## Сборка

```bash

cmake ..
```

Либо откройте `CMakeLists.txt` в Qt Creator и нажмите «Собрать».

## Запуск

1. Запустите НСУ, нажмите **«Открыть канал»**: приложение слушает UDP-порт `14540`.
2. Запустите эмулятор БПЛА с целевым адресом `127.0.0.1:14540`.
3. Убедитесь, что статус «Связь установлена», счётчики растут, график высоты обновляется.
4. Задайте высоту взлёта и нажмите **«Взлёт»**, в журнале появится результат `COMMAND_ACK`.
5. Нажмите **«Отключить БПЛА»**: через 3 секунды связь будет потеряна, команды заблокируются.
6. Запустите эмулятор снова: связь восстановится, команды снова доступны.

## Тестовые сценарии

| № | Входные данные | Ожидаемый результат |
|---|---|---|
| 1 | НСУ запущена, порт закрыт | «Связь отсутствует» |
| 2 | Нажата «Открыть канал» | UDP-порт открыт, ошибок нет |
| 3 | Эмулятор шлёт телеметрию 10 Гц | Метки обновляются, счётчик растёт |
| 4 | Пакет повреждён | Ошибка отображена, данные не применены |
| 5 | Пакеты 11 и 12 не отправлены | Счётчик потерь +2 |
| 6 | «Взлёт», 80 м | Отправлена `MAV_CMD_NAV_TAKEOFF` |
| 7 | `COMMAND_ACK: ACCEPTED` | «Команда принята» |
| 8 | `COMMAND_ACK` не получен за 3 с | «Подтверждение не получено» |
| 9 | Эмулятор остановлен | Через 3 с «Связь потеряна», кнопки заблокированы |
| 10 | Эмулятор снова запущен | «Связь установлена», кнопки разблокированы |
